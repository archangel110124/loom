### Findings worth keeping

- **Grass is cheap.** 0.054 ms for 45,460 blades at 1080p/4x MSAA — 0.3% of a 16.7 ms
  frame. The whole forward pass of every scene in the project is 0.05–0.11 ms. **So the
  placement compute pass and `vkCmdDrawIndirect` queued next in the design doc are not
  justified by GPU cost.** They become right when placement must be *dynamic* — a field
  larger than one CPU bake, streaming as the camera moves — which is a scale argument, and
  it needs an ADR first because hand-porting Voronoi clumping into Slang is the CPU/GPU
  divergence S2 and ADR 0006 exist to prevent.
- **The offscreen harness's ~30 ms/frame is the PNG encoder**, ~10 ms fixed plus ~11 ms per
  megapixel. GPU readback is 0.61 ms of it. It never measured the engine in either
  direction.
- **No gate in this project can detect an absent feature.** Validation layers cannot object
  to a draw call never made; a flicker metric cannot object to a subject not in frame. Both
  of tonight's biggest defects were of this shape, and both needed a human to look at a
  window.
- **`cargo xtask validate` does not run the windowed path over `SCENES`.** It renders 17
  offscreen and opens a window for exactly two hardcoded scenes, `blockout` and `cave` —
  neither with grass or particles. `meadow` is in that list now.

## 5. Gaps a critic flagged that I did **not** close

Ordered by how much I think they matter.

1. **Flicker is not invariant to brightness.** The same geometry painted lighter scores
   higher. `meadow` moved 2.712 → 3.059 on a colour change alone. Normalising by local mean
   would fix it. **This metric has now been wrong in three separate ways in one night —
   framing, animation, and scale — so treat this as load-bearing.**
2. **Draw distance is 55 m to literally zero.** That is a lawn, not a landscape grass
   system; UE5 runs hundreds of metres on mesh LODs. The falloff is being asked to do LOD's
   job by deleting the field, mitigated by "author the ground the colour of grass", which
   works top-down in a still and will not survive walking toward the horizon. **A real
   second LOD tier is the single biggest thing missing.**
3. **No frustum culling.** Every blade is expanded to 42 vertices every frame whether or not
   it is behind the camera. Cheap today; not free at scale.
4. **The timestamp granularity is one `forward` pass** covering sky, meshes, grass,
   particles and the MSAA resolve. Isolating grass needed an A/B between two scenes. The
   per-frame TLAS rebuild is a separate submit and is not counted at all.
5. **The blade vertex count (42) is written three times in two languages** —
   `scene.slang`'s `GRASS_VERTS`, `renderer.rs`, `viewer.rs`. Change the segment count and
   two draws silently under-draw.
6. **`assets/test/meadow.loom`'s header comments are false** — they still say blades are
   "generated on the CPU into an ordinary mesh" and that wind "cannot sway" them. Both
   stopped being true at slice 4, and this file is a golden reference.
7. **`height_jitter: 0.35` is hardcoded** in `loom_cli`, duplicating `Rules::default()`, and
   is unreachable from the schema.
8. **`loom_grass::coverage`'s `at` argument is field-local in production but world-space in
   tests.** Harmless today; it anchors the break-up noise to the field origin, so two
   identical fields at different world positions get an identical ragged boundary.
9. **`loom explode` never calls `set_grass`**, so there is no runtime carve path where grass
   is redrawn — the no-floating-blades property holds by re-baking at load only.
10. **The `Viewer` is not GPU-instrumented** (frames in flight need a pool per frame), so the
    instrument exists only on the path whose cost profile the real game never has.
